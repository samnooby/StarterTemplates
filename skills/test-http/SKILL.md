Exercise the HTTP API in `$0` (default: the current project): $ARGUMENTS

## Command

```
bash "${CLAUDE_PLUGIN_ROOT}/harness/with-app.sh" \
  --cwd <project dir> --port <port> --timeout 60 \
  --start "<start command>" \
  --check "cd '${CLAUDE_PLUGIN_ROOT}/harness' && pnpm -s http <absolute path to spec.json>"
```

`detect-app.sh` gives the start command and port. Exit code 0 means every request matched; 1 means at least one did not; 65 means the port was busy; 66 or 67 mean the app died or never became ready, with the last log lines printed.

## Spec format

```json
{
  "baseUrl": "http://127.0.0.1:3000",
  "requests": [
    { "name": "health", "path": "/health", "expect": { "status": 200, "body": { "status": "ok" } } },
    {
      "name": "create todo",
      "method": "POST",
      "path": "/todos",
      "headers": { "authorization": "Bearer test" },
      "body": { "title": "ship it" },
      "expect": { "status": 201, "headers": { "content-type": "application/json" }, "bodyIncludes": { "title": "ship it" } }
    },
    { "name": "unknown route", "path": "/nope", "expect": { "status": 404, "bodyText": "not found" } }
  ]
}
```

- `method` defaults to `GET`. A `body` is sent as JSON with `content-type: application/json` unless you set the header yourself.
- `expect.status` is exact. `expect.headers` values are substring matches. `expect.body` is deep equality. `expect.bodyIncludes` is a partial deep match (extra fields in the response are fine). `expect.bodyText` is a substring of the raw body. Use any combination.
- Requests run in order, so a create followed by a read works, but IDs generated by the server cannot be carried between requests. For those flows, assert the create with `bodyIncludes` and read a fixture ID, or write a short script.

## Writing a good spec

- One request per behaviour changed, plus one that proves the failure path (validation error, not found, unauthorised).
- Assert the fields that matter with `bodyIncludes`, not the whole body with `body`, unless the whole body is the contract.
- Keep the project's `harness.spec.json` as the smoke suite: health, one happy path per resource, one failure per resource.
